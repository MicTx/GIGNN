# 安全

GIGNN 是本地 Python 库。其主要安全边界是不可信表格数据、几何对象、图边、检查点文件、研究产物元数据，以及调用方提供的输出路径。

## 信任边界

| 输入 | 信任模型 | 守卫 |
| --- | --- | --- |
| 特征表 `X` | 不可信用户数据 | 必须是有限数值的 pandas `DataFrame`；行/特征上限适用。 |
| 标签 `y` | 不可信用户数据 | 长度、非空、缺失值与有序类契约均校验。 |
| 几何 | 不可信对象 | 只调用预期的坐标或拓扑方法；自动图规模有上限。 |
| `edge_index` | 不可信类数组图输入 | 形状、dtype、范围、非空与边数上限均强制。 |
| 检查点路径 | 由应用暴露时的不可信本地路径 | 直接与自动检查点在检查时拒绝已存在于最终路径的符号链接；调用方仍须把路径限制在应用自有根目录内，并防止并发路径替换。 |
| 直接检查点载荷 | 验证前不可信 | 保存只接受 weights-only 安全的容器/标量/张量并归一化 NumPy 标量；加载用 `weights_only=True` 加精确估计器模式/资源检查。 |
| 自动检查点归档 | 验证前不可信 | 文件/成员/解压尺寸上限、精确成员名、重复拒绝、JSON 模式、NPY 头/哈希/dtype/形状检查与语义载荷校验。 |
| 研究产物输出 | 本地文件系统路径 | 符号链接/非产物覆盖守卫、有界表格/元数据、CSV 公式转义。 |
| 绘图 `output_path` | 本地文件系统路径 | 创建父目录；暴露给用户时应用应约束路径。 |

## 直接估计器检查点

`GIGNNClassifier.load()` 使用：

```python
torch.load(path, map_location="cpu", weights_only=True)
```

直接检查点载荷必须只含 weights-only 安全的值：`None`、字符串/字节、布尔、整数、PyTorch 序列化支持的有限或非有限 Python 浮点、精确基类 `torch.Tensor`，以及以基本类型为键的嵌套字典/列表/元组。NumPy 标量在写入前转换为其原生 Python 等价物。自定义对象、张量子类、任意 NumPy 数组、循环容器、深于 100 层的嵌套以及超过条目上限的载荷在替换目标前即被拒绝。估计器检查点还必须恰好包含 `params`、`state_dict`、`classes`、`n_features_in` 与 `feature_names_in`；加载器拒绝非法估计器参数、类数过多、特征元数据非法、非张量状态值、张量数过多、张量元素过多以及超过 `MAX_CHECKPOINT_BYTES` 的文件。

直接写入方对临时文件 fsync、原子替换目标，并在平台/文件系统支持目录描述符时对父目录 fsync。显式的不支持目录错误视为可移植性限制；意外 I/O 错误正常传播。若 `os.replace` 之后父目录 fsync 失败，新文件可能已存在而 `save_checkpoint` 抛出——内容存在但目录项持久性未确认。

该格式仍面向更低层的估计器，惯例使用 `.pt` 后缀。

## 自动工作流检查点

`GIGNNAutoClassifier.save/load` 使用独立的 `.gignn` 归档。读取归档时不调用 `torch.load`。

容器是 ZIP 文件，包含：

- `metadata.json` 作为第一个且唯一的元数据成员；
- `arrays/array-NNNN.npy` 数值数组成员；
- JSON 引用把每个数组绑定到其种类、路径、dtype、形状、元素数与 SHA-256。

加载器拒绝：

- 符号链接检查点文件、文件缺失、文件超限、解压后归档超限；
- 重复、加密、目录、类路径穿越、意外或数量过多的成员；
- 不支持的压缩以及超大、畸形、含非有限值、重复、过深或过大的元数据；
- 对象/字符串 NPY 数组、非法 NPY 头、Fortran 序数组、摘要不匹配、意外字节长度、非有限浮点数组或总元素过多；
- 缺失/未被引用/重复的数组引用；
- 不兼容的归档、载荷或包主/次版本；
- 非法的选择器元数据、有序类、目标/切分索引、报告、训练损失、模型参数或 state dict 上限。

写入方在目标目录创建临时文件、fsync、强制最终尺寸上限，并原子替换请求的普通文件路径。暴露检查点路径的应用仍须使用有根的应用目录，因为父目录穿越是调用方级别的路径授权问题。

## 研究产物导出

`export_research_artifacts` 把传入的 DataFrame、ID、预测、概率、模拟报告、溯源信息与输出路径全部视为不可信输入。它校验行/单元格上限、概率形状与取值、元数据深度/条目上限以及已存在输出的所有权。以电子表格公式前缀开头的 CSV 单元格会被转义。除非 `include_raw=True`，原始行不包含在内。

## 文件路径指引

写文件的库函数包括：

- `GIGNNClassifier.save(path)`
- `GIGNNAutoClassifier.save(path)`
- `export_research_artifacts(output_dir, ...)`
- 带 `output_path` 的绘图函数

若把 GIGNN 包装进 Web 服务、CLI、notebook 网关或批处理平台，请把用户标识解析为应用自有路径，而不是接受任意文件系统路径。直接检查点的符号链接检查覆盖检查时刻稳定的最终路径；它不是抗竞态的 `openat`/`O_NOFOLLOW` 路径授权边界。面对并发或对抗性文件系统变更的应用必须在 GIGNN 之外实施该边界。不要为恢复一个不兼容文件而禁用检查点或产物守卫。

## 不可信数据指引

调用 GIGNN 前建议的调用方检查：

- 载入 pandas 前限制输入文件大小。
- 把行数与特征数限制在预期运行边界内。
- 校验特征名与预期模式。
- 空间语义重要时在 GIGNN 之外校验几何来源与 CRS。
- 超大数据集优先使用显式 `edge_index`，而非自动几何图构建。
- 把不可信检查点与产物位置放在源码、包与凭据目录之外。

GIGNN 也在代码内强制资源上限；见[数据契约](DATA_CONTRACT.md)。

## 依赖边界

核心 ML 执行依赖 PyTorch 与 PyTorch Geometric。从官方来源安装平台对应的 wheel。避免把未审查的私有包索引混入发布环境。

## 无运行时机密

当前包代码不需要环境变量、API 密钥、服务凭据、数据库或网络调用。

## 报告安全问题

对于私密安全问题，不要开含漏洞细节的公开 issue。通过项目约定的私密渠道向维护者提供最小复现、受影响版本、预期影响与相关产物哈希。
